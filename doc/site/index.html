Install before pub.dev

This is a standalone repository. Until a hosted package is actually published, use a Git dependency, not a presumed pub.dev release. The following tracks main, the development branch; it is not an immutable release pin.

dependencies:
  dartaframes_arrow:
    git:
      url: https://github.com/richardrh/dartarrow.git
      ref: main

For reproducible applications, select and review a real repository commit, then replace ref: main with its full commit ID. Obtain that ID from your checked-out revision with git rev-parse HEAD, or from GitHub's commit page; do not invent a hash. Commit the application's lockfile as well.

dart pub get

Import the core independently of any FFI support:

import 'package:dartaframes_arrow/arrow.dart';

See the official Git dependency documentation for revision resolution.

Arrays, schemas, batches and owned JSON

Create logical values, retain nulls, and give each batch column a matching schema field. The second slice argument is a count, not an end index.

import 'package:dartaframes_arrow/arrow.dart';

void main() {
  final type = ArrowIntegerType(32);
  final array = ArrowArray(type, [
    ArrowIntegerValue(10),
    null,
    ArrowIntegerValue(30),
  ]);
  final slice = array.slice(1, 2); // [null, 30]; shared storage
  final schema = ArrowSchema([ArrowField('value', type)]);
  final batch = RecordBatch(schema, [slice]);

  const codec = OwnedBatchJsonCodec();
  final text = codec.encode(batch);
  final restored = codec.decode(text);
  print(restored.length); // 2
  print(restored.columns.first[1]);

  final object = codec.toJson(batch);
  final fromObject = codec.fromJson(object);
  print(fromObject.length); // 2
}

RecordBatch checks column count, column types, equal lengths and field nullability. batch.slice(start, count) slices all columns with the same range. A zero-column batch can specify its row count with rowCount:.

Owned JSON is not Arrow IPC

OwnedBatchJsonCodec copies logical data into a package-specific JSON representation. It is neither a zero-copy transport nor the Arrow integration JSON format. Wide integers and temporal counters use decimal strings; floating-point values preserve raw IEEE bit patterns as hexadecimal data. Top-level dictionaries carry dictionary storage, but dictionaries nested in child arrays are rejected with UnsupportedError, not silently flattened.

The codec defaults to nesting depth 64, collection size 100,000 and source length 16 Mi characters. These limits are constructor options. Decoding validates the owned representation rather than accepting arbitrary JSON as an Arrow batch.

Borrowing, aliases and zero-copy slices

ArrowArray.fromBuffers imports little-endian physical buffers without copying their bytes. It exposes read-only views, but that does not make an existing writable alias immutable or transfer ownership.

import 'dart:typed_data';
import 'package:dartaframes_arrow/arrow.dart';

final bytes = Uint8List(8);
final words = ByteData.sublistView(bytes);
words.setInt32(0, 10, Endian.little);
words.setInt32(4, 20, Endian.little);
final borrowed = ArrowArray.fromBuffers(
  ArrowIntegerType(32),
  length: 2,
  buffers: [null, bytes], // no validity bitmap: every value is valid
);
final last = borrowed.slice(1, 1);
// Keep the backing allocation alive; do not mutate bytes or words
// while borrowed or last is in use.
  • Keep every backing allocation alive through the lifetime of the array and all derived views, including children and dictionaries. Do not release external/native storage early.
  • Do not mutate any backing alias while an imported array is in use. Read-only Dart views do not prevent another alias from changing bytes.
  • Buffer zero is the optional LSB-first validity bitmap. Null validity means all valid; nullCount: -1 means unknown. Required data buffers must be present even when empty.
  • A slice is a constant-time view sharing buffers, children and dictionary; it advances a logical offset without copying or scanning values. It does not compact storage or shorten the backing allocation's lifetime. Reading values, counting nulls and encoding JSON are separate work.
  • Offsets and lengths must fit the provided physical storage. List offsets address child logical index zero, including when the child itself is sliced. Parent validity masks a null parent without requiring child storage to be null.

Supported scope, not the whole Arrow specification

  • Null, booleans; signed and unsigned integers at 8, 16, 32 and 64 bits; floating-point at 16, 32 and 64 bits.
  • Decimal128-style storage with precision 1–38 and scale 0–precision; normal and large UTF-8 and binary offsets.
  • Dates, timestamps (including timezone metadata), durations and time values with the units represented by the API.
  • Lists, fixed-size lists, structs, integer-indexed dictionaries and extension types backed by a supported storage type.

int128 and uint128 are binding extensions, not Apache Arrow integer types. Extension storage support does not implement arbitrary extension-specific semantics.

Unsupported families include maps, dense and sparse unions, intervals, fixed-size binary, string/binary/list views, large lists and run-end encoding. Decimal widths/precision outside the exposed decimal type are not supported. There is no Arrow IPC reader/writer, file/stream serialization engine, compute kernel layer or native runtime. No additional platform coverage is implied by extraction into this repository.

Optional Arrow C ABI declarations

import 'package:dartaframes_arrow/arrow_c.dart';

This separate, dart:ffi-dependent library declares the standard CArrowArray, CArrowSchema and CArrowArrayStream structs. The core arrow.dart does not import FFI.

These are ABI layouts, not an owner, allocator, C-to-Dart import engine or release manager. Callers integrating native producers must manage allocations, callbacks, release ordering and stream errors according to the Arrow C interfaces. Importing these structs does not install or start a native runtime.

Conformance evidence: missing is not failing

The committed physical fixture at test/conformance/fixtures/pyarrow.json is generated independently by PyArrow 26.0.0. It deliberately includes families outside this package's supported scope; the Dart implementation is not its oracle.

mkdir -p build
dart run test/conformance/dart_probe.dart --output build/conformance.json

A pass is a successful probe; missing records an unsupported capability; fail records an actual mismatch or failure. A default successful report means no actual failures, not full Arrow support. Read status counts and individual results rather than treating process success as a blanket compatibility claim.

Use the optional strict gate when your acceptance policy requires every fixture capability:

dart run test/conformance/dart_probe.dart --output build/conformance.json --require-full

--require-full fails on missing capabilities as well as actual failures. It is intentionally stricter than the default supported-scope gate and can fail for the documented unsupported families.

Regenerate fixtures independently

python3 -m venv .venv
.venv/bin/python -m pip install -r tool/conformance/requirements.txt
.venv/bin/python tool/conformance/generate_fixtures.py

The requirements pin is pyarrow==26.0.0. The generator resolves its default output relative to the package, not your working directory. Review the fixture diff, rerun the Dart conformance probe and tests, and retain the report with the tested revision. Do not change expected data simply to make a mismatch disappear.

GitHub-first releases and provenance

The release path is a manually initiated draft GitHub release, not automatic pub.dev publication. A maintainer reviews validation results, the selected revision/tag, release notes and assets before making a draft public. A workflow-created draft is not proof that a release was published.

Use the validated source archive and its accompanying SHA256SUMS asset when supplied by a release. Verify the checksum before extracting, and record the release tag and commit. GitHub's automatically generated source downloads are distinct from a separately validated archive; a digest establishes byte integrity against the checksum you trust, not an independent signature or a promise of compatibility.

For publication readiness, run dart pub publish --dry-run from the standalone package. A dry run checks the package without publishing it; this repository's release workflow does not run a pub.dev publish step. Do not infer hosted availability from version 0.1.0, a tag or a GitHub release.

See actual releases and their assets for available artifacts. The intended project Pages URL is richardrh.github.io/dartarrow/; this guide does not assert that a deployment is already live.

Build and browse locally

With the repository's pinned Dart 3.13.0 SDK on PATH, resolve the package first. The builder uses only Python's standard library, clears only build/site to remove stale pages, copies this guide and CSS, then invokes dart doc --validate-links on the resolved local package. Pass --dart followed by an absolute SDK executable path to select Dart explicitly. No Hugo or site dependencies are required.

dart pub get
python3 tool/build_docs.py
python3 -m http.server 8000 --directory build/site

Open localhost:8000; the API reference is at relative api/ and the stylesheet at style.css. These relative paths also work beneath the project Pages prefix /dartarrow/. The build produces build/site/index.html, build/site/style.css and build/site/api/index.html.
