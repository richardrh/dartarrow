dartarrow · package 0.2.0

PyArrow-shaped tables in pure Dart

dartaframes_arrow provides typed scalars, buffer-backed arrays, schemas and real chunked tables without a native runtime or Polars dependency. This is scoped core behavior, not full PyArrow support.

Install before pub.dev

This is a standalone repository. Until a hosted package is actually published, use a Git dependency, not a presumed pub.dev release. The following tracks main, the development branch; it is not an immutable release pin.

dependencies:
  dartaframes_arrow:
    git:
      url: https://github.com/richardrh/dartarrow.git
      ref: main

For reproducible applications, select and review a real repository commit, then replace ref: main with its full commit ID. Obtain that ID from your checked-out revision with git rev-parse HEAD, or from GitHub's commit page; do not invent a hash. Commit the application's lockfile as well.

dart pub get

Import the core independently of any FFI support:

import 'package:dartaframes_arrow/arrow.dart';

See the official Git dependency documentation for revision resolution.

Arrays, typed scalars and chunked tables

Construct native values with dtype factories. Indexing returns a typed Scalar even for null; explicit conversion returns native values. Slice's second argument is a length, not an end index.

import 'package:dartaframes_arrow/arrow.dart' as pa;
import 'package:dartaframes_arrow/json.dart';

void main() {
  final values = pa.array([10, null, 30], type: pa.int32());
  print(values[1].isValid); // false
  print(values[0].asDart()); // 10
  print(values.slice(1, 2).toDartList()); // [null, 30]
  final schema = pa.schema([pa.field('value', pa.int32())],
      metadata: {'producer': 'Dart'});
  final batch = pa.RecordBatch.fromArrays([values], schema: schema);
  final table = pa.table({
    'value': pa.chunkedArray([values.slice(0, 1), values.slice(1)]),
  });
  print(table.column('value').numChunks); // 2
  print(table.toBatches(maxChunkSize: 2).map((b) => b.numRows));
  const codec = OwnedBatchJsonCodec();
  print(codec.decode(codec.encode(batch)).numRows); // 3
}

Batch columns are Array; Table columns are always ChunkedArray. Table retains chunk boundaries until combineChunks(). Projection and slicing preserve positive height even with zero columns. Use RecordBatch.fromStructArray for an explicit zero-column struct carrier.

Field and Schema preserve duplicate/empty names and nullable declarations. Metadata accepts String or Uint8List keys/values, preserves arbitrary bytes, and uses immutable content-based lookup. Absent versus empty metadata remains visible; default equality ignores metadata. Name lookup rejects duplicate ambiguity. Constructors permit physical nulls under a nonnullable field, as PyArrow does.

Precision is explicit

Scalar conversion returns int or BigInt without lossy wide-integer doubles. DecimalValue retains unscaled BigInt and scale. Temporal Scalar.value exposes the raw int/BigInt counter; Scalar.type retains units/timezone. asDart returns UTC DateTime or Duration when exactly representable, otherwise TemporalValue. Time-of-day, nanosecond remainders, IANA-zone timestamps and out-of-host-range values retain that exact representation. NaN is valid, not null; rawBits exposes exact IEEE bits.

Dart adaptation: Array and ChunkedArray expose a lazy .scalars Iterable rather than implementing Iterable: its generic cast<R>() conflicts with Arrow's dtype cast. Iterate with for (final scalar in values.scalars); materialize native values with .toDartList(). There is no native .toList() alias.

array.isValid() and array.isNull(nanIsNull: false) return non-null Boolean masks; ChunkedArray provides the corresponding chunked masks. Read an element's validity with array[i].isValid, not an indexed array method. Dictionary masks decode dictionary nulls while scalar validity describes the encoded index.

Owned JSON is not Arrow IPC

OwnedBatchJsonCodec, scalarToJson and scalarFromJson live in the separate json.dart import. They provide a package-specific JSON representation, not Arrow integration JSON or IPC. Wide integers and temporal counters use decimal strings; floating-point values preserve raw IEEE bit patterns. Metadata uses explicit byte encoding and legacy string metadata still decodes. Nested dictionary encoding is rejected, not silently flattened.

The codec defaults to nesting depth 64, collection size 100,000 and source length 16 Mi characters. These limits are constructor options. Decoding validates the owned representation rather than accepting arbitrary JSON as an Arrow batch.

Borrowing, aliases and zero-copy slices

Array.fromBuffers imports little-endian Buffer objects without copying their bytes. Read-only views do not make writable aliases immutable or transfer ownership.

import 'dart:typed_data';
import 'package:dartaframes_arrow/arrow.dart' as pa;

final bytes = Uint8List(8);
final words = ByteData.sublistView(bytes);
words.setInt32(0, 10, Endian.little);
words.setInt32(4, 20, Endian.little);
final borrowed = pa.Array.fromBuffers(
  pa.int32(), 2, [null, pa.Buffer(bytes)],
);
final last = borrowed.slice(1, 1);
// Do not mutate bytes or words while borrowed or last is in use.
// Buffer.slice shares memory; Buffer.toBytes materializes a copy.
  • Keep every backing allocation alive through the lifetime of the array and all derived views, including children and dictionaries. Do not release external/native storage early.
  • Do not mutate any backing alias while an imported array is in use. Read-only Dart views do not prevent another alias from changing bytes.
  • Buffer zero is the optional LSB-first validity bitmap. Null validity means all valid; nullCount: -1 means unknown. Required data buffers must be present even when empty.
  • A slice is a constant-time view sharing buffers, children and dictionary; it advances a logical offset without copying or scanning values. It does not compact storage or shorten the backing allocation's lifetime. Reading values, counting nulls and encoding JSON are separate work.
  • Offsets and lengths must fit the provided physical storage. List offsets address child logical index zero, including when the child itself is sliced. Parent validity masks a null parent without requiring child storage to be null.

Supported scope, not the whole Arrow specification

  • Null, booleans; signed and unsigned integers at 8, 16, 32 and 64 bits; floating-point at 16, 32 and 64 bits.
  • Decimal32/64/128/256 storage (precision up to 9/18/38/76) with signed 32-bit scale, including negative scales.
  • UTF-8 and binary with normal or large offsets or views (stringView(), binaryView()); fixed-size binary (binary(n)).
  • Dates, timestamps (including timezone metadata), durations, time values, and year-month, day-time and month-day-nano intervals (exact IntervalValue).
  • Lists, large lists, list views, fixed-size lists, structs, maps (mapType), sparse and dense unions, run-end encoding (runEndEncoded), integer-indexed dictionaries (including nested) and extension types backed by a supported storage type.

Maps convert to ordered lists of Dart (key, value) records. Unions and run-end encoded arrays have no validity bitmap: nullCount is 0 as in PyArrow, while scalars and masks report the selected child's validity. Build them from child arrays with Array.fromSparseUnion, Array.fromDenseUnion and Array.fromRunEnds.

bindingInt128() and bindingUint128() expose binding extensions, not Apache Arrow integer types. Extension storage support does not implement arbitrary extension-specific semantics.

Standard Arrow IPC streams and files are available from the separate ipc.dart import; see the Arrow IPC guide. There is no compute kernel layer, dataset layer or native runtime.

Optional Arrow C ABI declarations

import 'package:dartaframes_arrow/arrow_c.dart';

This separate, dart:ffi-dependent library declares the standard CArrowArray, CArrowSchema and CArrowArrayStream structs. The core arrow.dart does not import FFI.

These are ABI layouts, not an owner, allocator, C-to-Dart import engine or release manager. Callers integrating native producers must manage allocations, callbacks, release ordering and stream errors according to the Arrow C interfaces. Importing these structs does not install or start a native runtime.

Conformance evidence: missing is not failing

The committed physical fixture at test/conformance/fixtures/pyarrow.json uses independent PyArrow 26.0.0 expectations. Two legacy interval cases are explicitly labelled Arrow-format literals, not PyArrow-produced arrays; their per-case producer and specification source record this provenance. Every fixture family is now supported; the Dart implementation is not its oracle.

mkdir -p build
dart run test/conformance/dart_probe.dart --output build/conformance.json

A pass is a successful probe; missing records an unsupported capability; fail records an actual mismatch or failure. A default successful report means no actual failures, not full Arrow support. Read status counts and individual results rather than treating process success as a blanket compatibility claim.

Use the optional strict gate when your acceptance policy requires every fixture capability:

dart run test/conformance/dart_probe.dart --output build/conformance.json --require-full

--require-full fails on missing capabilities as well as actual failures. CI runs this strict mode; all 300 physical cases currently pass.

Regenerate fixtures independently

python3 -m venv .venv
.venv/bin/python -m pip install -r tool/conformance/requirements.txt
.venv/bin/python tool/conformance/generate_fixtures.py

The requirements pin is pyarrow==26.0.0. The generator resolves its default output relative to the package, not your working directory. Review the fixture diff, rerun the Dart conformance probe and tests, and retain the report with the tested revision. Do not change expected data simply to make a mismatch disappear.

GitHub-first releases and provenance

The release path is a manually initiated draft GitHub release, not automatic pub.dev publication. A maintainer reviews validation results, the selected revision/tag, release notes and assets before making a draft public. A workflow-created draft is not proof that a release was published.

Use the validated source archive and its accompanying SHA256SUMS asset when supplied by a release. Verify the checksum before extracting, and record the release tag and commit. GitHub's automatically generated source downloads are distinct from a separately validated archive; a digest establishes byte integrity against the checksum you trust, not an independent signature or a promise of compatibility.

For publication readiness, run dart pub publish --dry-run. No workflow publishes to pub.dev. Version 0.2.0 is a new breaking main revision; the existing v0.1.0 tag/draft is immutable and must not be overwritten. Do not infer hosted availability from a version, tag or draft.

See actual releases and their assets for available artifacts. The intended project Pages URL is richardrh.github.io/dartarrow/; this guide does not assert that a deployment is already live.

Migrating from 0.1.0 and Polars

Use the canonical classes DataType, Field, Schema, Array, Scalar, Buffer, RecordBatch, ChunkedArray and Table. Replace wrapper construction with pa.array(nativeValues, type: pa.int32()); use RecordBatch.fromArrays(..., schema: ...), numRows/numColumns and explicit scalar/native conversion. Factory names are lowerCamelCase: field, schema, recordBatch, table, chunkedArray, boolType, nullType, listType. No aliases or shims remain. Prefix the Arrow import with pa when Polars also exports Scalar.

Build and browse locally

With the repository's pinned Dart 3.13.0 SDK on PATH, resolve the package first. The builder uses only Python's standard library, clears only build/site to remove stale pages, copies this guide and CSS, then invokes dart doc --validate-links on the resolved local package. Pass --dart followed by an absolute SDK executable path to select Dart explicitly. No Hugo or site dependencies are required.

dart pub get
python3 tool/build_docs.py
python3 -m http.server 8000 --directory build/site

Open localhost:8000; the API reference is at relative api/ and the stylesheet at style.css. These relative paths also work beneath the project Pages prefix /dartarrow/. The build produces build/site/index.html, build/site/style.css and build/site/api/index.html.
