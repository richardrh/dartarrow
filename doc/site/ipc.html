Standard Arrow IPC streams and files

package:dartaframes_arrow/ipc.dart reads and writes Apache Arrow IPC format V5 entirely in Dart, shaped like pyarrow.ipc. FlatBuffers metadata is implemented in-tree; there is no native runtime.

Read and write in memory

import 'package:dartaframes_arrow/arrow.dart' as pa;
import 'package:dartaframes_arrow/ipc.dart' as ipc;

void main() {
  final table = pa.table({'id': pa.array([1, 2], type: pa.int64())});
  final stream = (ipc.newStream(table.schema)..writeTable(table)).close();
  final restored = ipc.openStream(stream).readAll(); // Table

  final file = (ipc.newFile(restored.schema)..writeTable(restored)).close();
  final reader = ipc.openFile(file);
  print(reader.numRecordBatches);
  print(reader.getBatch(0).toDartList());
}

openStream returns a RecordBatchStreamReader (schema, readNextBatch() returning null at end of stream, single-pass iteration, readAll()). openFile returns a RecordBatchFileReader (schema, numRecordBatches, getBatch(i), readAll()). newStream/newFile return writers with writeBatch, writeTable(table, maxChunkSize:), write and close(), which returns the complete bytes. File-system I/O is left to the caller.

Uncompressed bodies are read as zero-copy views: the returned arrays borrow the input Uint8List, so keep it alive and unmodified. Writers serialize directly from the arrays' physical buffers and rebase slices (bitmaps realigned, offsets rebased, run ends trimmed). Run dart run example/arrow_ipc.dart for a complete example.

Supported standard families

FamilyCoverage
PrimitiveNull, boolean, signed/unsigned 8/16/32/64-bit integers, float16/32/64 with raw bit preservation
Binary and textUTF-8, binary, large offsets, fixed-size binary, string/binary views with variadic buffers
DecimalDecimal32/64/128/256, including negative scales
TemporalDates, times, timestamps with time-zone metadata, durations, year-month/day-time/month-day-nano intervals
NestedLists, large and fixed-size lists, list views, structs, maps
DictionaryRoot and nested dictionaries, extension-wrapped dictionaries, stream replacement and deltas
Other layoutsSparse/dense unions and run-end encoding
MetadataSchema and field metadata as raw bytes; extension annotations
StructureMultiple and empty batches, zero rows, positive-row zero-column batches

Writers send a dictionary when it first appears, a delta batch when a later dictionary extends the previous one, and (streams only) a replacement when it otherwise differs. File writers reject replacements, which the file format cannot represent.

The web LZ4 decoder checks bounds, frame structure, back-references and declared sizes. It consumes but does not verify frame checksums; do not treat it as an integrity or authenticity check. External LZ4 dictionaries are unsupported. Decompressed sizes are bounded by the message-size limit.

Limits, errors and deliberate exclusions

  • Little-endian IPC only; big-endian input raises UnsupportedError.
  • IpcLimits bounds nesting depth, fields, rows, total decoded values, buffers, message bytes, dictionaries and batches. Defaults are conservative; pass raised limits for larger trusted input.
  • Malformed input raises FormatException, never an out-of-bounds read. Unknown codecs or types raise UnsupportedError.
  • bindingInt128()/bindingUint128() are binding extensions with no standard encoding; writers reject them.
  • A field has one extension annotation. Stacked extensions and dictionaries whose value type is an extension are rejected on write; use the canonical extension-over-dictionary form. Supply annotations through ExtensionType, not reserved ARROW:extension:* field metadata.
  • ExtensionType.metadata is a String, so non-UTF-8 extension metadata is rejected as malformed. Other metadata is preserved as raw bytes.
  • This is not a claim of complete Apache Arrow specification conformance.

Independent verification against PyArrow 26

test/conformance/fixtures/arrow_ipc/ holds PyArrow 26.0.0 stream and file outputs for every family above, with a manifest and JSON expectations. Tests compare schema, metadata, nulls, batch boundaries, dictionary values and indices, exact floating bits, unscaled decimals and temporal counters. Ordinary Dart tests read these fixtures without Python.

Dart reads all 90 fixture files; it rewrites 88, and PyArrow reads and validates all 88. The remaining two are the file and stream forms of the deliberately rejected non-UTF-8 extension metadata.

python3 -m venv .venv
P=.venv/bin/python
$P -m pip install -r tool/conformance/requirements.txt
$P tool/conformance/arrow_ipc_interop.py check
$P tool/conformance/arrow_ipc_interop.py verify --self-test
dart run tool/conformance/arrow_ipc_interop.dart --out build/arrow_ipc_dart
$P tool/conformance/arrow_ipc_interop.py verify --output build/arrow_ipc_dart

The final command reports the two non-UTF-8 extension metadata cases as missing, not failed. CI runs these steps and the IPC tests under dart2js.
