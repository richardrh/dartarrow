# Contributing

Requires Dart 3.13.0 (pinned in `mise.toml`) and, for conformance work, Python 3.12.

```sh
mise run check
```

Tests need no native library. Changes to Arrow support must keep unsupported
cases explicit rather than reporting them as passing.

## PyArrow conformance

Fixtures are generated by PyArrow 26.0.0 and committed; the Dart implementation
is never its own oracle.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r tool/conformance/requirements.txt

# Physical layout fixtures
.venv/bin/python tool/conformance/generate_fixtures.py
git diff --exit-code -- test/conformance/fixtures/pyarrow.json
dart run test/conformance/dart_probe.dart --require-full

# Public API oracle
.venv/bin/python tool/conformance/generate_api_fixtures.py --output /tmp/api_pyarrow.json
cmp test/conformance/fixtures/api_pyarrow.json /tmp/api_pyarrow.json
dart test test/conformance/api_conformance_test.dart

# Arrow IPC: PyArrow fixtures read by Dart, Dart output verified by PyArrow
.venv/bin/python tool/conformance/arrow_ipc_interop.py check
dart run tool/conformance/arrow_ipc_interop.dart --out build/arrow_ipc_dart
.venv/bin/python tool/conformance/arrow_ipc_interop.py verify --output build/arrow_ipc_dart
```

The probe reports `pass`, `fail` (mismatch) and `missing` (unsupported).
`--require-full`, used in CI, also fails on `missing`. Never edit expected data
to make a mismatch disappear.

## Releases

Manual and GitHub-first. Validate a green `main` commit, create the matching
annotated tag (e.g. `v0.2.0`), then dispatch the release workflow. It produces a
**draft** GitHub release with a source archive and SHA-256 checksums for review.
Nothing publishes to pub.dev. Existing tags are immutable.
